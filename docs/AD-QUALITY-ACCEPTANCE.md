## 1. 投放级验收硬标准（Checklist）

录屏与手玩统一用竖屏 **390×844**（或真机 9:16）。门户另测一条。任一 P0 条失败，整包打回，不接受「截图已换」。

**C1 跟手（指哪到哪）**

- 测法：鼠标或手指按在路面上。路面左右边缘在屏幕上的位置事先标出。点在路面 20%、50%、80% 三处，各停 0.5 秒；再做一次 200ms 内横扫约 70% 路面宽度。standalone 与门户 iframe 各做一遍。
- 通过：松手后队长停在该点，不回中。到位后 120ms 内，队长世界坐标与「手指在路面上的投影」误差 ≤ **0.25** 世界单位，队长屏幕横坐标与手指误差 ≤ **8% 屏宽**。快扫结束时过冲 ≤ **0.35** 世界单位。两套容器（窄屏 / 宽 iframe）用同一套误差。
- 打回：仍用 `(clientX / innerWidth)` 的相对位移乘 `roadHalfWidth`；或镜头横向仍约为 `playerX * 0.08`，人滑离手指。

**C2 关长与决策密度**

- 测法：`node games/gate-runner/tests/core-test.mjs` 打印每关 `length / runSpeed`。手玩 L1、L5、L10 各一局，从「开始」后第一帧移动计时，到结算卡弹出停止，菜单和结算不计入。
- 通过：脚本时长与手玩时长都在 **15.0–30.0 秒**。L1 ≥ 18s，L5 ≥ 20s，L10 在 **22–30s**。门对间隔按该关 `runSpeed` 折算为 **2.0–3.5 秒**一座。每关至少 **1** 对门含减员（`sub`，人数最低扣到 1）。至少 **6** 关满足 `needPeople ≥ startPeople + 6`。第一座门在开跑后 **2.0–3.5 秒** 进入可射击距离。
- 打回：任一关脚本时长 < 15s 或 > 30s；或全程只有加法/乘法门。

**C3 强制战斗（认真玩 ≠ 贴边摆烂）**

- 测法：两条无渲染脚本（见第 4 节），外加总监各手玩一局。贴边 = 开局把 x 打到右夹紧 `+(roadHalfWidth - 0.4)` 直到结束，开火仍自动。认真 = 每对门走数值更高的一侧，阻塞波次留在弹道能覆盖的横向上直到清空。
- 通过：认真脚本 **胜**，且击杀 ≥ 该关 `threeKills`。贴边脚本 **负**（人数归零，或到终点 `people < needPeople`）。手玩复现同一胜负。阻塞波的碰撞并集盖住夹紧位：玩家在 `x = ±(roadHalfWidth - 0.4)` 时仍与至少一只怪重叠。允许波次中间留 **≤ 0.8** 世界单位的缝，不允许贴护栏整波落空。正中 `x = 0` 必须吃到本对门的其中一扇（现在门在 `±1.55`、判定是严格 `< 1.55`，正中两扇都漏）。
- 打回：贴边仍能通关；认真脚本失败；或终点出现「先击败 Boss」后超过 **8 秒** 打不着怪（现逻辑：Boss 继续往 `-Z` 走，子弹只往 `+Z`，会软锁）。

**C4 人数视觉膨胀**

- 测法：调试命令或测试门把人数依次打到 1、3、8、16、24，看路面小队和弹道，不看 HUD 数字。
- 通过：1–3 人 = 同数全身；4–8 人 ≥ **5** 具身体；9 人及以上前排 **7–10** 具，并有世界空间 `+N`（N = 人数 − 可见身体）。身体全部在路面内，脚底贴地。弹道数在 1 / 4 / 8 / 16 人四档肉眼变密，上限可留在 7 发，但 16 人与 3 人必须一眼能分开。`+N` 在 9 人时出现。
- 打回：可见身体仍是 `Math.min(3, people)`，或只涨 HUD。

**C5 音效**

- 测法：竖屏、系统音量打开、游戏未静音。打门、穿门、命中、击杀、掉人、Boss 受击、胜、负各触发一次。再点静音重做一遍。门户 iframe 里重复「穿门、击杀」。
- 通过：上述 8 类都有可分辨的合成音（Web Audio 即可，不要等外部音频文件）。第一下指针按下后出声。静音立即全灭，刷新后记住。胜负音不同。iframe 内同样出声。
- 打回：任一战斗反馈无声，或只有 BGM 没有事件音。

**C6 Juice / VFX**

- 测法：手玩 L1 前两座门和第一波怪，慢放录屏。
- 通过：穿门粒子 ≥ **12** 颗，颜色随门类型，挂在 `fxGroup` 里，存活 ≥ **0.4s**。浮动字（`+8` / `×2` / `-3`）上浮 ≥ **400ms**。普通击杀震屏 **80–160ms**；Boss 击杀幅度 ≥ 普通的 **2 倍**，时长仍 ≤ 200ms。死亡不是当场 `visible=false`：击退或倒地 ≥ **400ms**，动画结束事件再移除。门在默认曝光下有一圈可辨的辉光；Bloom 强度落到 **0.45–0.8**、阈值 ≤ **0.65** 这一档，天空不发白、Sam 不被糊掉。前方同时看得见 **2–3** 对门的 3D 板，HTML 大字只标最近一对。
- 打回：`fxGroup` 仍为空；死亡仍靠 `setTimeout(500/900)` 隐藏；只显示最近一对门、其余 3D 板整段关掉。

**C7 Boss**

- 测法：`?level=5` 与 `?level=10` 各手玩两局：一局正面输出，一局贴边。
- 通过：L5、L10 各有一场必打 Boss。Boss 在玩家前方 **16–22m** 现身，开火全程开启，出生即可受伤。Boss 横向威胁盖住夹紧位。未击杀不能结算胜利。认真火力 **5–8 秒** 击杀；火力不足时 **12 秒** 内人数被磨光并失败，不允许无限对峙。竖屏里迷你龙高度约占画面 **28–40%**，终局龙 **35–50%**。血条在交战期间连续下降。死亡有 ≥ **0.6s** 的倒地或爆开，然后才消失。
- 打回：为了不挡镜头把终局龙压到高度约 2.3；存在无敌展示、熄火、或终点软锁；贴边不掉血也能把 Boss 耗死或卡死。

**C8 竖屏 15s / 30s 成片**

- 测法：390×844 系统录屏，游戏音开，一镜到底，不剪。15 秒条用 L1。30 秒条用 L5 或 L10 整关。
- 通过：
  - 15 秒条：开跑 **3 秒** 内同时出现路面、发光数字门、小队、枪口火光、路面上的尸群。全程开火无 **≥ 0.4 秒** 空窗。至少 **1** 次人数暴涨（身体或 `+N` 变了）。至少 **4** 次带受击反馈的击杀。无钉场定格。
  - 30 秒条：整关玩法时长落在 15–30 秒，含 Boss 血条下降，结尾结算卡 ≤ **2 秒**。不得用菜单空镜把时长短的关卡垫成 30 秒。
  - 与 `casual-minigames/docs/refs/doom-gates.jpg` 对照五项：高架路面、黄黑警示边、超大发光数字、成团尸潮、脚下小队可读。五项里至少 **4** 项总监点头。
- 打回：3 秒内仍是空路或菜单；怪站桩无敌；只有 HUD 在涨；画面是随机蓝灰盒子城。

**C9 门户 iframe**

- 测法：根目录静态服打开 `http://localhost:8080/`。桌面宽度 ≥ 1200px 看中栏；再把窗口收到 ≤ 760px。在 iframe 里重做 C1 跟手和 C5 穿门音。切换到 SameGame 再切回来。
- 通过：桌面门户的游戏区是居中 **9:16** 框（左右留边），iframe 内 `innerWidth` 不再等于整块舞台宽。跟手误差与 standalone 相同。切走后 Gate Runner 的声音停止。`allow="autoplay"` 保留。SameGame 仍能独立打开。
- 打回：iframe 被拉成横条，同一手指行程在门户里和单页里位移差一倍以上。

红线（碰一条即整包打回）：任一关短于 15 秒；任一关 `startPeople ≥ needPeople`；贴边脚本通关；认真脚本失败；录屏里有 ≥ 0.4 秒熄火或无敌定格；无事件音；人数到 16 仍只有 3 具身体且没有 `+N`。

## 3. 改还是重写

局部重写三块，关卡表整表重铺。三块是：输入与镜头、遭遇导演（含删除 `readableWave`）、成长表现（小队与弹道）。保留场景加载、glTF、门运算纯函数、结算壳和门户。

理由：现在的失败集中在为截图加的定格、相对拖动和人数硬顶，以及一份「起点就能过终点」的关卡表。加载器和资产不是投放失败的原因，整仓重写会把已经贴地的角色和路面问题再引入一次。

不要再在 `readableWave` 上打补丁。钉场、慢爬、熄火、无敌写在同一段 `update` 里，补一处会把另一处留成广告空窗。

## 4. 给开发员工的第一张任务单（P0）

只做 P0-1 到 P0-5。不做 Bloom 精修，不重做城市，不开新美术需求。

规格：

- 指针每帧用「路面在屏幕上的左右边界」做绝对映射，得到 `targetX`。禁止 `(clientX / innerWidth) * 2 - 1` 的相对增量。松手停在最后的横向位置。镜头横向跟随要满足 C1 的 8% 屏宽；现系数 `0.08` 作废。平滑可以继续用大约 `dt * 12`，但目标点必须已经是手指位置。
- A/D 与方向键每次 ±0.45 世界单位，夹紧在 `±(roadHalfWidth - 0.4)`，与屏宽无关。
- 删除 `readableWave` 的全部运行时行为，字段从 JSON 去掉。具体删掉这几段：距事件 14m 才显示、钉在 `state.z + 8.5` 满 1.6 秒、展示期 `castShadow` 开关、展示期缩放 1.12、`showcaseHold` 停火、`if (z.readable && !z.showcased) continue` 的子弹无敌、`approachSpeed = 0.45` 这种「为了好看所以追不上」的速度。怪从生成起可见、可受伤、可碰撞，脚底贴路。
- 动画切换只用 mixer 的结束事件。删掉受击 350ms、死亡 500ms、Boss 死亡 900ms、Boss 挥击 600ms 这四个 `setTimeout`。
- 普通怪默认迎面速度维持能在玩家跑速下形成约 **0.6–1.0 秒** 交战窗的相对速度。要更长的射击窗口就加长队列或让怪成墙站住，禁止再把人和开火一起冻住。
- 每关至少两波 `block: "full"`。该波在 `x = ±(roadHalfWidth - 0.4)` 仍发生碰撞。缝宽 ≤ 0.8。Boss 横向威胁同样盖住夹紧位。
- 终点：`people < needPeople` 失败。Boss 存活时，要么 Boss 在 **8 秒** 内被拉回射程且全路宽可击中，要么直接判负。禁止 `state.z` 卡住、Boss 往 `-Z` 走远。
- 正中必须吃到一扇门。每关至少一对 `sub`。`needPeople ≥ startPeople + 6` 至少 6 关。全关玩法时长 15–30 秒，L1 ≥ 18，L10 为 22–30。

## 5. 总监验收流程（强制）

此流程取代 `games/gate-runner/SELFTEST.md` 的截图清单，也取代 `selftest-shots*` 目录。截图只可作附件，不能作为通过依据。`SELFTEST.md` 里的镜头数字与现包不符，整份勾选表作废。

1. 开发先交三样：`core-test` 通过日志、认真/贴边两条脚本的胜负和星级、L1 与 L10 的时长（脚本值与手玩值）。任一红线失败，总监不开始手玩。
2. 总监本人玩，不看开发录的演示。窗口 390×844。L1、L5、L10 各三局：认真选门、贴左夹紧、贴右夹紧。认真局必须能胜；两局贴边必须失败。用秒表核对关长。
